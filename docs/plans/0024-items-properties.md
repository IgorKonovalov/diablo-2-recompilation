# 0024 — Items: base stats and properties

> **Status:** in-progress (approved 2026-10-14)
> **Created:** 2026-10-14
> **Owner skill(s):** archivist, reverser, spec-writer
> **Related ADRs:** 0001-target-toolchain-evidence-sources, 0003-runtime-experiments, 0004-boundary-oracles-in-reproduction, 0007-fetched-leads-only, 0010-forced-path-runs

## TL;DR

**Question:** once an item's base, quality and rows (unique, set, affixes) are chosen, what values does it end up
with, and which draws on the item seed produce them? The question covers two parts:
- **The base stats** that `sub_00557AB0_ItemInitStats` sets before the quality switch: quantity, durability, defense
  and the picture.
- **The property roll:** `sub_0065FEC0_ItemApplyProps` turns a row's `prop`/`par`/`min`/`max` blocks into item stats
  through `Properties` and `ItemStatCost`. Its post-switch neighbours are covered too: ethereal
  (`sub_00556CA0_ItemRollEthereal`) and sockets (`sub_00556B60_ItemRollSockets`, `sub_0062BC20_ItemMaxSockets`).

Plans 0019 and 0021 take the property roll as an ADR-0004 seed oracle. This plan reads it, models it in
`tools/props.py`, and replaces the oracle. When it is done:
- `docs/findings/items/0006-properties.md` has the roll at `[C]` for the logged cases;
- `docs/specs/items/properties.md` is drafted;
- [save/d2s](../specs/save/d2s.md), held at draft because each property's meaning belonged here, can be reviewed.

### Phase 1 — Read the base stats and the property roll
- **Owner skill:** reverser
- **What:** read `ItemInitStats`, `ItemApplyProps` with its per-`func` handlers, and the ethereal and socket rolls,

- **Outputs:**
  - `docs/findings/items/0006-properties.md`;
  - `re/symbols.csv` rows (subsystem `items/properties`);
  - `re/types/` additions (the property and stat-list records).
- **Done when:** the finding states, with addresses and `[I]` or better:
  - **base stats:**
    - quantity, durability and max durability (`nodurability`, ethereal);
    - defense from `minac`/`maxac`, with the draw and range;
    - the picture/variant draw (`invfile` variants for rings, amulets and charms);
    - the order of these draws on the unit seed or item seed.
  - **the property roll:**
    - how a row's `(prop, par, min, max)` blocks are walked, and in which order;
    - per `func`, what it draws: the range, whether `min == max` skips the draw, how `par` is used, and which stats
      it writes;
    - how a row's block count is chosen for affixes, and set `add func` handling;
    - which `func` values call the calc VM.
  - **ethereal and sockets:**
    - the ethereal test (which qualities and bases, the draw);
    - the socket count draw: the base's `gemsockets`, the type's `MaxSock1/25/40` against ilvl, the clamps, the
      draw range;
    - their order relative to the quality builders.
  - **stat storage:** how a property becomes stat-list entries (`ItemStatCost` `op`, `op param`, `op base`,
    `op stat1..3`), as far as the drop path needs it to predict the saved stats.
  - **the boundary decision** for Phase 2: which handlers (calc-driven ones, skill-granting ones) are oracles.
    Recommend one; the architect rules at the review.

## Open questions

- Formula-driven properties (`data/calc`): this plan names them and leaves them as oracles. A `data/calc` plan
  follows if they matter on the drop path.
- Set bonuses (`Sets` partial and full blocks) apply when worn, not when created. Only the creation-time roll is in
  scope, and the bonus stats are noted for `player/*`.
- Runeword and gem/rune socket filling are `items/sockets-runewords`. Only the empty socket count is in scope.
- Vendor and gamble creation reuse the roll through other callers (`items/vendors`).
