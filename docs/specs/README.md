# Specs — research map

This is the deliverable. Each subsystem gets a directory `docs/specs/<subsystem>/` containing a
`README.md` (overview, data flow, entry points) plus one file per algorithm. The `architect` owns
this map; the `spec-writer` owns the files under it.

Status values: `not started` · `findings in progress` · `draft spec` · `reviewed`

Scope is set by [ADR-0001](../adrs/0001-target-toolchain-evidence-sources.md) and extended by
[ADR-0002](../adrs/0002-scope-creation-paths-and-enablers.md) and [ADR-0014](../adrs/0014-scope-game-simulation.md), with
ADR-0017 and [ADR-0025](../adrs/0025-scope-item-use-inventory.md) (game rules: quests, travel, the economy, item use and
inventory), ADR-0022 (the server frame) and [ADR-0026](../adrs/0026-scope-in-game-message-layer.md) (the in-game message
layer; transport, compression, encryption, Battle.net, realm and handshake stay out). By the owner's 2026-10-30 ruling
plans beyond the approved roster (0038, 0046, 0050, 0052, 0054, 0055, 0056, 0057–0062; from 2026-11-10 also 0063–0068, approved by the owner; 0063 and 0068 closed 2026-11-10) may be drafted but not started;
when the roster finishes, the project stops and reports to the owner.
The table has four bands. **Core** is the original goal. **Enablers** are systems the core can't be reproduced
without. **Creation paths** are other callers into the core item and monster code. **Simulation** is the game run
over time, checked per event (ADR-0014). Core rows come first, so "the original three areas are done" stays visible.

### Out of scope (ADR-0002, ADR-0005, ADR-0014, ADR-0025, ADR-0026)

The network protocol below the in-game message layer (transport, compression, encryption, Battle.net, realm and the
pre-game handshake; the message layer itself is in by ADR-0026, row `net/messages`), the client's trade window (the trade itself is in by ADR-0033, row `items/trade`), sound, fonts, video, rendering and input handling. Wall-clock timing, frame pacing and the
client's prediction or display of values are out as well: simulation claims are stated in game frames and from the
server's outcomes (ADR-0014). Presentation formats (palettes, DT1 pixels, DC6/DCC/COF) are decoded as **tooling only**
under ADR-0005 (plan 0006): format docs and `tools/` decoders, output in `workspace/render/`, and no row or spec here.
Animation timing enters as frame counts and hit frames (ADR-0014 phase 5); animation playback does not. Which cel and
colour shift the game picks for an item is read in [items/0003](../findings/items/0003-item-graphics.md) (`[I]`, plan
0015) as the reference for `tools/item_art.py`; it stays a finding, not a row (architect, 2026-10-12). Player against
player and hostile states are specified from the code (`[I]`) except where a two-client run reached them (the
two-client harness, [ADR-0008](../adrs/0008-two-client-harness.md), accepted 2026-10-16; plan 0044's
run:2026-10-20-two-clients raised the 17 % on physical and lightning damage and the party aura filter). A spec that touches a simulation phase not yet planned
specifies it only to the depth it needs and lists the rest under *Open questions*.
