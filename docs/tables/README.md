# Excel tables

One file per table (`Levels.md`, `TreasureClassEx.md`…). Owned by `archivist`. The column template
is in `.claude/skills/archivist/references/table-doc-template.md`. Semantics a column only gets from
*code* (how the game interprets it) are added by the `reverser` through a finding link, never
guessed here.

## Source and shape

Every table under `data/global/excel/` in `workspace/merged/` (built from the 1.14b reference
archives d2data → d2exp → LoD patch_d2; see [mpq.md](../formats/mpq.md)). Generated by
`python3 -I tools/excel_survey.py workspace/merged workspace/logs/merged-manifest.tsv`.

- `[C]` **Both forms ship.** 97 table basenames: 87 have a `.txt` *and* a `.bin`, 5 are `.txt` only
  (`Aiparms`, `MonName`, `SoundEnviron`, `TreasureClass`, `WeaponClass`), 5 are `.bin` only
  (`leveldefs` plus four `*code.bin` files). No excel file comes from d2data: d2exp or patch_d2
  overrides all 56 of its tables.
- `[C]` **Every one of the 87 pairs agrees on record count.** The `.bin`'s leading u32 equals the
  `.txt` data rows (57 tables), or the data rows minus the `Expansion` marker rows (30 tables).
  `(size − 4)` is an exact multiple of that count in every case ([excel-bin.md](../formats/excel-bin.md)).
- `[C]` **Five pairs mix archives.** The `.bin` comes from a different archive than its `.txt`:

  | table | `.txt` from | `.bin` from |
  |---|---|---|
  | `automagic` | d2exp | patch_d2 |
  | `RarePrefix` | d2exp | patch_d2 |
  | `RareSuffix` | d2exp | patch_d2 |
  | `inventory` | patch_d2 | d2exp |
  | `PlrMode` | patch_d2 | d2exp |

  `[C]` patch_d2 replaced `automagic.bin`, `rareprefix.bin` and `raresuffix.bin` (content changed
  against d2exp, `workspace/logs/overrides.txt`) without shipping a new `.txt`. For `inventory` and
  `PlrMode` it replaced the `.txt` and left d2exp's `.bin`. Row counts agree in all five.
- `[C]` For `automagic`, `RarePrefix` and `RareSuffix` the patch only changed the **record format**
  (132 → 144 and 60 → 72 bytes); decoded cell by cell, the patch_d2 `.bin` equals the d2exp `.txt` in
  every compiled column (1 440 + 552 + 1 860 cells, 0 mismatches). Either side may be cited for their
  content. Details: [excel-bin.md § Mixed-archive tables](../formats/excel-bin.md#mixed-archive-tables-automagic-rareprefix-raresuffix).
  `inventory` and `PlrMode` are not yet diffed; until they are, decode the `.bin` and diff it against
  the `.txt` before citing either.
- `[C]` **The game reads the `.bin`.** Every table is loaded from `DATA\GLOBAL\EXCEL\<name>.bin`; the
  `.txt` is only parsed under `-txt`, which recompiles it to a loose `.bin` that the game then reads
  only with `-direct` as well `[I]`. So in a stock run `automagic`/`RarePrefix`/`RareSuffix` use the
  patch_d2 `.bin` and `inventory`/`PlrMode` the d2exp `.bin` (the patch_d2 `.txt` edits are not
  live) `[I]`. See [data/0001](../findings/data/0001-excel-loader.md#answer-summary) and
  [data/0002](../findings/data/0002-mpq-precedence.md).
- `[C]` **`treasureclassex` is the live TC table; `TreasureClass.txt` (707 rows, txt only) is never
  loaded.** The `treasureclass` string in `Game.exe` is an `itemtypes` column name
  ([data/0001](../findings/data/0001-excel-loader.md#answer-summary)).
- `[C]` 86 of the 88 `.bin` tables are loaded; `cubemod` and `cubetype` are not (their names do not
  occur in `Game.exe`) ([data/0001 §4](../findings/data/0001-excel-loader.md#4-record-size-corroboration-all-88-bin-tables)).

Decoding and diffing a table: `python3 -I tools/excel_bin.py diff workspace/merged/data/global/excel <table>`
(layouts in `tools/excel_layouts.py`; `probe` helps find a new table's layout). The encoding rules
(blank cells, codes, string keys, index columns) are in [excel-bin.md](../formats/excel-bin.md#cell-encoding-rules).
`python3 -I tools/excel_bin.py survey workspace/merged/data/global/excel` diffs every laid-out table at once;
the docs gate runs it as the `excel_layout` survey (`tools/gate.py --full`) against a per-table baseline of
cells and mismatches.

Column legend: **Rows** is the `.bin` record count when there is a `.bin` with a count header,
otherwise the `.txt` data rows. **Rec** is the `.bin` record size in bytes. **Agree** is how the counts
match (`=` exact, `= (−n marker)` once the `n` `Expansion` marker rows are dropped).

## Item art index

`python3 -I tools/item_art.py index workspace/merged` writes `workspace/render/items/index.tsv` (never
committed, ADR-0005) and `missing.tsv` beside it. It is tooling for plan 0009, not evidence. It joins
the following, one line per row of [Weapons](Weapons.md), [Armor](Armor.md), [Misc](Misc.md),
[UniqueItems](UniqueItems.md) and [SetItems](SetItems.md) (1 188 lines: 306 + 202 + 151 + 402 + 127):

- **Identity:** kind, row index (the record index), code (bases) or `index` (uniques and sets), name,
  and the base item code of a unique or set row.
- **Inventory icon:** `data/global/items/<file>.dc6`, in the game's order `[I]` ([items/0003](../findings/items/0003-item-graphics.md) § 2): a set
  row's own `invfile`, else the base's `setinvfile`; a unique row's own `invfile` (row > 0 only), else
  the base's `uniqueinvfile`; then, if the base's item type has `VarInvGfx` > 0, the type's `InvGfx`;
  then the base's `invfile`. Bases take the last two steps. The set/unique steps apply to an
  identified item only, so the index shows the identified view. The `InvGfx` entry depends on a
  per-item picture index the table cannot know: the index takes `InvGfx1` and lists every candidate in
  `inv_var`. `inv_src` names the column used. In stock data the `VarInvGfx` step serves 7 bases
  (`amu`, `vip`, `rin`, `jew`, `cm1..3`), 30 uniques and 11 set items.
- **Drop animation:** `flippyfile`, the unique or set row's own, else the base's `[I]` (no
  identification test).
- **Colour transforms:** the base's `Transform`/`InvTrans` (integers) and the unique or set row's
  `chrtransform`/`invtransform` ([colors](colors.md) codes), side by side. They combine as
  [item-palette.md § Which file serves which item and view](../formats/item-palette.md#which-file-serves-which-item-and-view)
  says `[I]`; `tint` and `sheets` apply that, with no map for types 3 and 4.
- **Worn-art keys** (data-only reading of file names, `[L]`): the composit layer from the base's
  `component` (the row index into `composit.txt`; 16 means no layer), the DCC component code
  (`alternategfx`, or for body armour one [armtype](armtype.md) token per part), and `wclass`/`2handedwclass`
  for weapons. `worn_files` counts the player DCCs `chars/<cls>/<layer>/<cls><layer><code>*.dcc`.

Every path is looked up case-insensitively in `merged/`. On the merged tree with `d2char` (3 512 COFs)
1 reference is missing: the drop animation `flptail` of the unused Misc row `tal`, a file present in
no extracted archive. The inventory icons of the five token and essence rows 145..149 (`invtoa`,
`invtes`, `invceh`, `invbet`, `invfed`) were missing before because they were unnamed entries in
`patch_d2.mpq`; the derived item-art name set in `tools/mpq_dump.py` now names and merges them (plan
0009 Phase 1). The `d2char` merge raised the player classes per worn key from 2 to 7 (1 for
class-only items).
`[C]` for the file counts (by script over the trees); the meaning of a missing file is `[L]`.

`[I]` `WeaponClass.txt` (no `.bin`) is not loaded by the game: it has no loader
([data/0001 §3](../findings/data/0001-excel-loader.md#3-what-is-registered-datatbls_loadall-0x00619300)).
Its codes are the weapon classes in COF and DCC names ([cof.md](../formats/cof.md)), and the
`wclass`/`2handedwclass` cells of Weapons use them, so the index shows those cells as they are.
