# ActClockTables: the act light clock's three tables (`Game.exe` image)

> **Source:** the pinned `Game.exe` image (no excel file)   **Tables:** 3, 18 rows (54 dwords): 48 values listed, 6 by rule   **Records:** six rows of three dwords
> **Doc status:** address, row layout and reader of each table; the values listed or given by a rule that the survey checks against the image ([ADR-0031](../adrs/0031-constants-of-the-code-image.md));
> the meanings taken from [frame/0001 § 3.1](../findings/frame/0001-tick-and-messages.md#31-actsclockpass-the-act-light-clock) with its tags
> (plan 0063 Phase 1, entry `2026-11-04-spec-writer-archivist-act-clock-tables`)

## Purpose

`ActClockTick` (0x0061C040) steps each act's light clock against three small constant tables. No MPQ file holds them and they are not an excel table:
they are constants of the code, so this doc sits beside [PathDirTables](PathDirTables.md) and [PathTypes](PathTypes.md), the other image-constant docs of
`docs/tables/`, and not under `docs/formats/` (no file format is described). The reader is [sim/frame § G1b](../specs/sim/frame.md#g-the-other-per-frame-passes);
the step that uses them is frame/0001 § 3.1. Generated and checked by `python3 -I tools/actclock_survey.py summary|md <game.exe>` (gate survey `actclock`).

## Layout

- `[C]` The three tables are contiguous in the image's data: `g_ActClockTable0` at `0x007443F0`, `g_ActClockTable1` at `0x00744438`, `g_ActClockTable2` at `0x00744480`
  (re/symbols.csv), 72 bytes each, the next at the address that follows (`0x007443F0 + 72 = 0x00744438`, `+ 72 = 0x00744480`; `0x00744480 + 72 = 0x007444C8`).
  Each is six rows of three little-endian dwords: **`start`** (offset 0), **`type`** (offset 4), **colour word** (offset 8). Row `p` is at `table + 12 p`.
- `[I]` Readers (frame/0001 § 3.1, "the xrefs to them are reads only"): `ActClockTick` and `ClockStep` (0x0061BEE0), which take `start` and `type` of row `p`
  (`start` multiplied by the clock's scale `k`) from table 0 when the clock's flag word `+0x30` is 0, else from table 2, and compare the next row's `start` against table 1
  in act index 3 and table 2 otherwise; 0x0061BCE0 blends two rows' colour bytes into `+0x18..+0x1A` of the clock. The exact step is the `[C]` block of frame/0001 § 3.1 (0x0061BF4F–0x0061BFA7).
- `[I]` The colour word is below `0x01000000` in all 18 rows (its top byte is 0), so it is a three-byte colour; which byte is red, green or blue is not read here `[L]`.
- `[I]` `start` is in the units of the clock's `c` counter over `k` (`c` is reset at `k * 360`; the largest `start` is 350). `type` is 0 to 3: frame/0001 § 3.1 tests `type == 2` in table 0 and copies `type` into `v` (`+0x04`); what a `type` value means to the client is not read.

- `[C]` **Rule, table 2's `start`:** `start(p) = 60 * ((p + 5) mod 6)`, that is 300, 0, 60, 120, 180, 240 for `p` = 0..5. It equals the image's six values (survey key `t2_start_rule_mismatches=0`); it is no claim about how the table was made.
- `[C]` Tables 0 and 1 have no rule known: their `start` columns (320, 340, 0, 160, 180, 200 and 340, 350, 0, 180, 190, 200) are not sorted by row and are listed above, as are every `type` and every colour word.

## Survey

`python3 -I tools/actclock_survey.py summary workspace/install/app/game.exe` prints `SURVEY actclock`: tables 3, rows 18, a crc32 of each table's 18 dwords, the rule's mismatches, and `doc_missing` and `doc_mismatches` (the 18 rows above against the image). It exits 1 on any mismatch and is baselined in `tools/gate/baselines/actclock.txt`.
